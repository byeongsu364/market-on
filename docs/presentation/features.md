## 3. 기술 구조 (발표 "기술성")

### 3-1. 온톨로지 + RAG를 한 PostgreSQL에
- 품목·품종·확인 포인트·단위·제철·수확 시기·산지·보관·레시피 재료(`usedIn`)를 **온톨로지 관계**로, 고르는 법·보관·손질·레시피 원문을 **RAG 청크**(bge-m3 임베딩, pgvector)로.
- **그래프 뷰**(`onto_node`·`onto_edge`·`rag_chunk`): 지식과 시장 데이터(점포·시세·제보·세일·입점 요청)를 **복사 없이** 한 그래프로 — `sells`·`hasPrice`·`reportedAt`·`supportedBy` 등. 사과 한 품목 그래프에 분류·제철·확인 포인트·품종·근거 문서·**파는 점포 54곳**·최근 시세가 함께 나와요.
- 검색은 **온톨로지가 먼저**: 질문 → 품목·의도 → 그 범위 안에서만 벡터 검색.

### 3-2. AI 역할 분담 — 젬마가 헤드
| 역할 | 모델 | 하는 일 |
|---|---|---|
| 사진 인식 | **구글 비전** | 품목 라벨 + 가격표 글자 (AI 모델에 사진을 보내지 않음) |
| 의도 나누기(route) | 규칙 → 젬마 | 키워드로 먼저, 안 되면 젬마 (중앙값 0.18초) |
| 계획(plan) | 제미나이 → GPT | 대화에서 도구 고르기 |
| 사실 뽑기(extract) | 제미나이 → GPT | 근거가 길 때 필요한 사실만 |
| **답 쓰기(write)** | **젬마** → 제미나이 → GPT | 최종 한국어 답 (젬마 73회, 중앙값 5.4초) |
| 이유 문장(reason) | 제미나이 → GPT → 젬마 | 장보기 이유 |
| 번역(translate) | **젬마만** | 다국어 (045) |
- 젬마는 학교 서버(자체 서빙, 비용 0). 외부 AI는 하루·시간당 호출 한도.

### 3-3. 환각을 막는 장치
- **숫자는 코드가**: 시세·수량·금액·제철·보관 온도는 코드와 온톨로지 값. AI는 문장만.
- **숫자 대조**: 답 문장의 숫자·단위·다른 품목 이름을 근거와 비교해 틀린 문장 삭제. 판정어("신선해요", "추천") 삭제.
- **출처 표시**: 실제로 쓴 근거의 출처, 검수 전 문서는 "검수 전".
- **범위 밖이면 지어내지 않음**: 목록에 없는 품목은 되묻고, 효능 단정은 거절하고, 가격 예측은 하지 않고 오늘 시세만.

### 3-4. 데이터 적재 파이프라인 (7단계 + 자동 검사 4개)
수집(이용 조건 확인된 API만) → 정제 → 정규화(온톨로지 ID 없는 문서 제외) → 청크 → **숫자 원문 대조** → 적재(바뀐 청크만 임베딩) → 캐시 정리. 검사: 온톨로지 연결·출처·라이선스(사실 관계만)·중복·제보 보류 — 실패하면 적재 중단.

## 5. 원칙 (발표에서 꼭 말할 것)
1. **판정하지 않아요**: "신선해요", "살 만해요"를 말하지 않고 확인 포인트·숫자 비교만.
2. **숫자는 코드가, 말은 근거 문서가**: AI가 숫자를 지어낼 수 없는 구조.
3. **출처 100%, 검수 상태 공개**: 검수 전 문서는 "검수 전"으로 숨기지 않고 표시.
4. **예시는 예시라고**: aT가 조사하지 않는 품종 시세는 "예시 시세 · 실제 조사값 아님".
5. **개인 정보 최소**: 사진 메타데이터 삭제, 위치는 동의 시 대략값, 제보 기기는 해시만, 리뷰 작성자 앞 3글자만.
