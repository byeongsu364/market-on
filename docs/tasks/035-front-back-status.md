## 1. 이미 맞춘 것 (실제 서버에 연결됨)
- 점포 리뷰, 손님 가입·로그인 (`customer`)
- 점포 가격: 상인 확인 → 손님 제보 → 시장 평균 순
- 점포 카테고리, 영업 중 여부, 결제 수단, 한 줄 소개, 거리(`distance_m`), 네이버 지도용 이름(`naver_name`)
- 가게 위치 저장(`PUT /merchant/store/location`). 지도 핀 좌표(`lat`/`lng`)는 상인이 위치를 확인한 점포에만 와요
- 시장 상세(`GET /markets/{id}`), 점포 수(`store_count`), 요청 수(`requests`), 가입 날짜(`/auth/me`의 `created_at`)

## 4. 알아 두면 좋은 것
- 지도 핀: 상가정보 좌표는 건물 위치라서(경동 108곳 중 101곳이 같은 좌표) 상인이 위치를 확인하기 전에는 좌표를 보내지 않아요. 좌표가 없을 때 화면은 평면도를 보여 주니 그 흐름을 그대로 둬요.
- 시장 평균 가격(`source: 'market_avg'`)은 점포의 실제 가격이 아니에요. 가격 비교나 "더 싼 점포" 목록에서는 빼요.
- 화면 테스트는 가끔 1개씩 실패하는 불안정성이 남아 있어요. 고친 뒤에는 전체를 여러 번 돌려 봐요.

## 5. 연결 확인 결과 (2026-11-27, main `6b11003`)
새 DB(pgvector, 마이그레이션 0001~0017, 온톨로지·문서 적재, 시연 시장 24곳)에 백엔드를 띄워 확인했어요. 외부 키(aT·공공데이터·AI)는 넣지 않았어요.

- **경로**: 화면 `src/api/*.ts`가 live에서 부르는 경로는 모두 서버에 있어요. 서버에만 있고 화면이 안 부르는 것은 `GET /admin/market-admins`, `POST /admin/market-admins/{id}/disable`뿐이에요.
- **응답 모양**: 시장·시장 상세·지도 점포·품목·제철·상인 점포 응답의 필드가 `types/contract.ts`와 맞아요.
- **흐름 32개 통과**:
  - 손님: 가입 → `/auth/me` → 리뷰 쓰기·목록·삭제 → 로그아웃. 비로그인 리뷰 쓰기는 401, 손님이 상인 API를 부르면 403
  - 가격 제보, 마감세일 목록, 시장 검색·요청 수, 품목 검색, 캡차
  - 상인: 가입 → 운영자 승인 → 로그인 → 점포 수정(소개·결제 수단) → 위치 저장 → 지도에 핀 좌표·결제 수단·소개가 나옴 → 가격 목록 → 마감세일 등록·조회수·종료 → 포스터
- **테스트**: 화면 5가지 검사 통과(테스트 166개), 백엔드 555개 통과·2개 건너뜀(DB 포함)
- **확인하면서 알게 된 것** (코드 문제 아님, 환경 설정):
  - 백엔드는 Python 3.11 이상이 필요해요(`datetime.UTC`).
  - 테스트 DB는 정렬을 `C`로 만들어야 `test_market_item_counts_active_only`가 통과해요(`create database … template template0 lc_collate 'C' lc_ctype 'C'`). 기본 `en_US.utf8`이면 한글 정렬이 달라요.
  - `.env`의 `LLM_ROUTES`를 기본값과 다르게 두면 `test_recognize.py` 4개가 실패해요.
  - `X-Device-Id`는 UUID여야 해요. 화면은 `crypto.randomUUID()`로 만드는데, 이 함수는 https나 localhost에서만 있어요. http로 IP 주소에 띄우면 가격 제보가 안 돼요.
  - 마이그레이션 번호 `0017`이 둘(`0017_media_photo_location`, `0017_store_location`)이에요. 이름순으로 둘 다 적용돼서 문제는 없지만, 다음 파일은 `0018`부터 써요.
- **아직 못 한 것**: 브라우저로 화면을 직접 눌러 보는 확인, 실제 키를 넣은 가격·AI 응답 확인.
