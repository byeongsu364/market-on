# 작업 지시서 045 · 다국어: 화면·품목 데이터·AI 답변 (en·zh·ja·vi)

- 담당: Codex · 지시: Claude · 2026-11-27 · 승인: 병수 ("AI 답변까지")
- 언어: 한국어(기본), English(en), 中文(zh, 간체), 日本語(ja), Tiếng Việt(vi) — 시안 Settings·판단 카드와 같음
- 원칙: **근거·검색·사실 확인은 한국어로 하고, 마지막에 젬마로 번역만**(병수 2026-11-27: "다국어는 젬마로 번역만 하자"). 번역문은 숫자·단위가 원문과 같아야 표시(아니면 한국어 원문 + 안내). 번역에는 "기계 번역" 표시. 출처 제목은 원문 그대로
- 범위: `frontend/`, `backend/`, `data/i18n/`(새). 패키지 추가 금지

## 1. 화면 문구
- `frontend/src/i18n/locales/{en,zh,ja,vi}.json`: `ko.json` 모든 키. 초안은 `scripts/translate_locales.py`(LLM 역할 `translate`, 아래 2장)로 만들고 파일 맨 위 `"_meta": {"machine_translated": true, "reviewed": false}`. 자리표시자 `{name}` 등 보존 검사
- Settings 언어 선택 → 저장(localStorage + 로그인 시 계정 `lang`), `<html lang>` 변경, API 요청에 `lang`
- 판단 카드: 선택 언어로 그림(폰트: zh/ja는 시스템 CJK 폰트 대체 확인)

## 2. 번역 역할 (040 헤드 구조에 추가)
- `LLM_ROUTES`에 `translate: [gemma]` — **젬마만**. 제미나이·GPT로 넘기지 않음. 젬마가 꺼졌거나 번역 검사를 통과하지 못하면 한국어 원문 + `translated: false` (기본값·.env.example)
- `llm/translate.py`: 한국어 → 대상 언어, 시스템 지시 "뜻을 더하거나 빼지 말 것, 숫자·단위·고유명사 그대로". 결과 검사 `knowledge/fact_check`의 숫자·단위 집합 비교(단위는 ℃·%·g·kg·원·개 기호로 정규화, "달/개월"은 숫자만 비교) + 판정·추천 단어(언어별 목록) 없음
- 번역 캐시: `response_cache`에 `tr:{lang}:{sha256(원문)}`

## 3. 품목 데이터
- `data/i18n/{en,zh,ja,vi}.yaml`: 품목·품종·단위·카테고리 이름(사람이 확인할 짧은 단어 — 초안은 번역 역할, `reviewed: false`), 확인 포인트 문장(번역 역할 초안), 제철·보관 템플릿 문장
- 적재: `entity_labels`에 언어별 라벨(kind `translated`), 확인 포인트는 응답 시 언어별 텍스트(없으면 한국어)
- API: `/items/*`, `/prices`, 지도·레시피 등 이름이 나오는 응답이 `lang`(쿼리 또는 `Accept-Language`)을 따름. 없는 값은 한국어

## 4. AI 답변
- `/ask` `lang`: ko 외 언어 허용. 흐름: (질문이 외국어면 `translate`(젬마)로 한국어로 바꿔) 의도·품목 인식 → 지금 한국어 경로 그대로(검색·write·fact_check) → 최종 한국어 답을 `translate` → 검사 통과 시 번역문, 실패 시 한국어 원문 + `translated: false`. 응답에 `lang`, `translated`, `original`(한국어) 포함
- 템플릿 답(제철·보관·시세·판매 점포·레시피 카드): **LLM 없이** `data/i18n` 템플릿·라벨로
- `/chat`: 사용자 메시지 언어를 그대로 `plan`에 주고(제미나이·GPT는 다국어), 최종 `write`는 한국어로 만든 뒤 `translate` — 대조 규칙 동일
- 장보기 이유 문장: 한국어로 만든 뒤 `translate`
- 캐시 키에 lang(이미 있음) 확인
- 화면: 답 아래 "기계 번역 · 원문 보기"(펼치면 한국어 원문)
