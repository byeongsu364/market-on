## 1. 요청 · 응답
```ts
type AskRequest = { question?: string; intent?: AskIntent; item_id?: string; market_id?: string; lang?: 'ko' };
type AskIntent = 'select' | 'store' | 'prep' | 'season' | 'price' | 'where';
type Citation = { title: string; publisher: string | null; url: string | null; license: string | null };
type AskResponse = {
  kind: 'answer' | 'no_evidence' | 'need_item' | 'price' | 'where' | 'out_of_scope';
  intent: AskIntent | null;
  item_id: string | null; item_name: string | null;
  answer: string | null;            // kind=answer일 때 한국어 2~4문장
  citations: Citation[];            // 답에 실제로 쓴 근거의 출처 (중복 제거)
  candidates?: { item_id: string; name: string }[];  // need_item일 때 (최대 5)
  price?: PriceView;                // kind=price일 때 기존 /price 응답 그대로
  stores?: { store_id: string; name: string }[];      // kind=where일 때
  model: string | null;             // 답을 만든 모델 (캐시·LLM 안 쓴 경우 null)
  cached: boolean;
  removed: number;                  // 값 대조로 뺀 문장 수
};
```
- `question` 또는 `intent` 중 하나는 필수 (칩 질문은 `intent`만, 자유 질문은 `question`). 질문 200자 이하
- `X-Requested-With` 필수(기존 CSRF), **`X-Device-Id` 기준 1시간 60회 초과 → 429 `TOO_MANY_QUESTIONS`** (GPT 비용 보호)

## 2. 처리 순서 (`services/ask_service.py`, 지식 단계는 `knowledge/`)
1. **의도**: `intent`가 오면 그대로. 아니면 **키워드 규칙 먼저** (`knowledge/ask_intent.py`: 보관·냉장·냉동→store / 손질·씻·다듬→prep / 제철·언제·철·품종·산지→season / 고르·고를·확인·좋은 거→select / 얼마·가격·시세→price / 어디·파는·가게·점포→where). 규칙으로 못 정하면 라우터 `ask` 작업으로 **보기 중 하나만** 고르게 함(JSON `{"intent": ...}`, 보기 밖이면 `out_of_scope`)
2. **품목**: `item_id`가 오면 그대로, 아니면 `ontology.resolve_entities(question)`에서 품목만. 없거나 여러 개면 `need_item` + 후보(질문 단어로 `/items/search`와 같은 검색)
3. **price / where는 LLM을 쓰지 않음**: price → `price_service`(market_id 있으면 그 시장 기준), where → `market_service` 판매 점포(market_id 필수, 없으면 422). 응답 `kind`에 맞춰 그대로
4. **캐시(D6)** `knowledge/answer_cache.py`: 키 = `ask:{item}:{intent}:{lang}:{서울 날짜}:{문서 버전}:{질문 해시 또는 'chip'}`
   - 칩 질문(`question` 없음)은 `chip`, 자유 질문은 정규화(공백·물음표 제거, 소문자)한 질문의 sha256 앞 16자
   - **문서 버전** = 그 품목 문서들의 내용 해시 합(문서가 고쳐지면 자동으로 새 키). `response_cache`에 `{answer...}` JSON + model 저장. 캐시 적중이면 `cached: true`, LLM 호출 없음
5. **검색**: `retriever.search(entity_ids=[item], intent=intent, lang, k=4, min_similarity=0.45)`
   - 근거 0개 → `no_evidence` ("이 품목의 ○○ 자료가 아직 없어요"), **LLM 호출 없음**
   - 근거 본문에서 **`>`로 시작하는 표시 줄과 `출처:` 줄은 빼고** LLM에 넘김 (출처는 citations로 따로)
6. **답변 생성** (프롬프트 `llm/prompts/ask.txt`, 라우터 작업 `ask`):
   - 번호 붙인 근거 `[1]…[4]`만 주고 "근거에 있는 내용만, 한국어 2~4문장, 해요체, 근거에 없으면 `answer: null`" — JSON `{"answer": str|null, "used": [1,2]}`
   - 금지: 신선도 판정·등급·구매 권유("신선해요", "A등급", "사세요", "추천") — 프롬프트에도 적고 5번 대조에서도 제거
7. **값 대조(D5)** `knowledge/fact_check.py` — 문장 단위:
   - 답 문장 속 **숫자+단위**(℃·도·일·주·개월·월·%·Bx·g·kg·원, 범위 `0~2℃`, 한글 수 `한 달`은 숫자로 바꿔 비교)가 `used` 근거 원문에 **같은 값으로 있어야** 함. 없으면 그 문장 제거
   - 질문 품목이 아닌 **다른 품목 이름**(온톨로지 라벨)이 근거에 없는데 나오면 그 문장 제거
   - 금지 표현이 있는 문장 제거
   - 남은 문장이 0개이거나 JSON이 깨졌으면 라우터 `accept`가 거절 이유(`invalid_json`·`unsupported`)를 돌려줘 **GPT로 다시**. GPT도 실패하면 `no_evidence`
   - `removed` = 뺀 문장 수, citations = `used`에 든 근거의 출처만
8. `llm_calls` 기록은 라우터가 함 (내용 저장 없음)

## 4. 테스트 (LLM·임베딩은 가짜)
- 의도 규칙 표(문장 12개 이상), 규칙 실패 → LLM 분류, 보기 밖 → out_of_scope
- 품목 없음·여러 개 → need_item, price·where는 LLM 호출 0회, where에 market_id 없음 422
- 캐시: 같은 칩 질문 두 번 → 두 번째 cached·LLM 0회 / 문서 내용 바꾸면 새로 생성 / 자유 질문은 질문별
- 근거 0개 → no_evidence·LLM 0회, 표시 줄·출처 줄이 LLM 입력에 없음
- 값 대조: 근거에 `0~2℃` → "0~2℃" 문장 유지, "5℃" 문장 제거 / "한 달" ↔ "1개월" / 다른 품목 이름 제거 / "신선해요" 제거 / 전부 제거 → GPT 재시도 → 그래도 실패 no_evidence
- 429, CSRF 403, 질문 200자 초과 422, 계약 키
- 기존 테스트 유지
