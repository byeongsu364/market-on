## 3. 서비스 한 줄 정의

**[확정]** 전통시장 현장에서 소비자가 상품을 찍으면 품목·시세·구매 지식을 보여 주고, 신선도는 소비자가 스스로 판단하도록 돕는 서비스예요. 시장 안 점포를 카테고리별 지도로 안내해서 여러 점포를 방문하게 이끌어요.

- 한 줄 버전: **"시장 안에서, 이 상품을, 내가 판단한다."**
- 사용자 흐름: 찍고(인식) → 판단하고(확인 포인트·시세) → 찾고(지도에서 점포) → 함께 산다(같은 시장 동선)

### 팀이 정한 원칙
- **[확정] 신선도는 소비자가 판단한다.** AI는 등급("A 신선", "바로 구매 추천")을 매기지 않고, 품목별 확인 포인트만 안내해요.
  - 예: 대파는 "잎 끝 마름·누런 잎 없음 / 흰 줄기가 단단하고 윤기 있음 / 뿌리 쪽 수분 유지"
  - 이유: AI 판정은 객관적 근거가 되기 어렵고, 틀렸을 때 책임 문제가 생겨요. 다른 신선도 앱들과 구별되는 점이기도 해요.
- **[확정] 시장 내 점포를 카테고리별 지도로 보여 준다.** (청과·채소·수산·정육·반찬·떡/분식 등)

## 4. 참가신청서 최신안

### 4-1. 추진 목적 (지도교수 의견 반영안 + 팀 보완)

> 전통시장 농축수산물은 품질과 가격을 비교할 정보가 부족하여 소비자가 구매를 망설이는 경우가 많다. 시장 현장에서 사진 한 장으로 품목을 인식하고 공공데이터 기반 시세정보를 제공하며, 온톨로지·RAG 기반 구매 지식을 활용하여 소비자가 신선도를 확인하고 합리적인 구매를 판단할 수 있도록 지원한다. 또한 시장 내 점포를 카테고리별 지도로 안내하여 여러 점포의 방문을 유도한다. 이를 통해 전통시장 구매에 대한 신뢰를 높이고 전통시장 이용 활성화와 소상공인의 판매 촉진에 기여하고자 한다.

- 지도교수 원안 기준으로 팀이 보탠 곳: "시장 현장에서"(차별점), "또한 시장 내 점포를 … 방문을 유도한다."(점포 지도)

### 4-2. 핵심 기능

1. 사진 기반 품목 인식 및 품목별 신선도 판별 지표 안내
2. 공공데이터(KAMIS) 기준시세로 전통시장·대형마트 가격 비교
3. 온톨로지·RAG 기반 구매 근거 제공(출하 시기·외관 품질 지표·저장 조건)
4. AI Agent 맞춤 구매 추천(가정용·선물용, 예산별)
5. 구매 판단 카드 생성·공유(다국어, 상인 홍보용)
6. 시장 내 점포 카테고리별 지도 및 인식 품목 판매 점포 안내

- 원본에 있던 "판매 로그 기반 구매 트렌드 대시보드"는 판매 데이터 출처가 없고 무박 일정에 비해 범위가 커서 뺐어요.
- 2번은 장볼지도(정부 앱)와 겹쳐요. **[제안]** "내가 보고 있는 상품이 기준시세보다 싼지"로 표현을 바꾸면 겹치지 않아요.
- 3번 괄호의 다른 후보: "(제철 시기·품질 선별 기준·저장 방법)", "(산지·출하 시기·관능 평가 기준·유통 저장 조건)"

### 4-3. AI 활용 도구

| 구분 | 활용 프로그램 |
|---|---|
| 생성형 AI | Gemini(멀티모달 품목별 신선도 확인 포인트 안내, 구매 설명 생성), Gemma [버전 확인](8bit 양자화 자체 서빙 LLM) |
| 이미지 생성 | Gemini 이미지 생성(구매 판단 카드·다국어 홍보 이미지) |
| 기타 AI | [지식] 온톨로지(지식그래프)·RAG(임베딩+벡터DB) / [비전] Google Cloud Vision API(품목 인식) / [바이브코딩] Claude Code·Cursor·ChatGPT |

### 4-4. 원본 대비 바뀐 점 요약
- 추진 목적: "근거가 없어 대형마트에 밀린다", "가치를 증명" → "정보가 부족해 구매를 망설인다", "신뢰를 높인다"로 덜 단정적으로 바꿈
- 신선도: "AI 신선도 판별" → "소비자가 판단, AI는 확인 포인트 안내"
- 기능: 6개 → 5개(대시보드 제외) → 점포 지도를 더해 다시 6개
- 기능 순서: 사진 인식을 1번으로, 온톨로지·RAG를 3번으로 옮김

### 6-2. 차별점 4가지
1. **쓰는 장소:** 집에서 "어디서 살까"가 아니라 시장 현장에서 "이걸 살까"를 판단해요.
2. **판단 주체:** AI 판정이 아니라 소비자가 확인 포인트로 직접 판단해요.
3. **근거의 출처:** 생성형 AI의 말이 아니라 온톨로지(구조화된 지식)와 RAG(문서 근거)를 써요. 동의어("대파 값"/"파 가격")를 같은 지식으로 묶고 출처를 보여 줘요.
4. **혜택 대상:** 소비자가 만든 판단 카드가 가게 홍보물이 되고, 다국어로 외국인 방문객도 써요.

### 6-3. 발표·신청서용 문구
> 기존 서비스가 집에서 "어디서 살까"를 알려 준다면, Market-On은 전통시장 현장에서 "이걸 살까"를 소비자가 스스로 판단할 수 있도록 온톨로지 기반의 근거를 제공하고, 그 판단 결과를 상인의 홍보 수단으로 연결한다.

> 기존 서비스가 "시장에 어떻게 가나(지도)", "집에서 어떻게 사나(배달)", "어디가 싼가(장볼지도)"를 해결했다면, Market-On은 시장 안에서 상품 앞에 선 순간의 판단을 돕는다.

- **[제안]** 발표에서 장볼지도를 먼저 언급하세요. 심사위원이 알고 있을 가능성이 높아요.
- **[확정]** 레시피 추천은 유지해요. 장볼지도 AI 레시피와 겹치므로, 재료를 같은 시장 안 점포로 연결하는 점을 강조해요.

## 7. 전통시장 활성화 방법 [확정]

### 7-1. 활성화 방법 통합표

| 문제 | 활성화 방법 | Market-On 기능 | 우선순위 |
|---|---|---|---|
| 품질·가격을 믿기 어렵다 | 현장에서 시세와 확인 포인트로 판단 근거 제공. 소비자가 찍은 가격표가 쌓여 **우리 시장 실시간 시세표** 생성 | 사진 인식, 기준시세 비교, 신선도 판별 지표 안내, 가격표 읽기·시장 시세표 | P0 |
| 상인의 경험이 손님에게 전달되지 않는다 | 상인이 30초 음성으로 고르는 법을 녹음하면 지식으로 저장, 확인 포인트에 "○○상회 사장님 노하우"로 표시 | 상인 노하우 지식화 (온톨로지·RAG) | P0 |
| 원하는 가게를 찾기 어렵다 | 시장 안 점포를 카테고리별로 보여 주고, 찍은 품목을 파는 점포를 강조 | 카테고리별 점포 지도 | P0 |
| 무엇을 사야 할지 모른다 | 품목·메뉴로 레시피를 추천하고 재료를 같은 시장 점포로 안내. 상인의 남는 재고에서 출발하는 **역추천** 포함 | 레시피 추천, 재고 레시피 역추천 | P1 |
| 젊은 층·외국인이 안 온다 | 공유하기 좋은 판단 카드, 다국어 지도와 주문 문장 | 판단 카드 공유, 다국어 | P1 |
| 저녁 재고가 남는다 | 마감 할인 정보를 주변 이용자에게 알림 (재고 역추천과 함께) | 마감 할인 알림 | P2 |
| 이용이 불편하다 | 주차장·화장실·고객센터·배송 가능 점포 표시 | 지도에 편의시설 층 추가 | P2 |
| 1인 가구에게 판매 단위가 크다 | 같은 시장 이용자끼리 "대파 1단 반 나누기" 매칭 | 반띵 장보기 | 발표 로드맵 |
| 시장에 갈 이유가 없다 | 온톨로지 출하 시기로 "이번 주 햇○○ 첫 출하"를 알리고 파는 점포 표시 | 첫물 알림 | 발표 로드맵 |

### 7-2. 심사위원에게 신선한 포인트
- **상인 노하우 지식화:** 상인이 홍보 대상이 아니라 지식 제공자가 됨. 마트에 없는 전통시장 고유 자산(상인 경험)을 데이터로 바꿈. 시연에서 녹음 → 지식 반영 장면이 강렬함
- **실시간 시장 시세표:** KAMIS는 지역 평균뿐이고 정부도 전통시장 가격 수집 방법을 정하지 못함. 사용자가 쓰기만 하면 시장별 가격이 쌓임. "가게 가격은 어디서 오나?" 질문도 해결
- **재고 레시피 역추천:** 장볼지도 레시피는 소비자 메뉴에서 출발, 우리는 상인 재고에서 출발. 레시피가 재고 소진 도구가 됨
- **반띵 장보기·첫물 알림:** 판매 단위 문제와 방문 동기를 정면으로 다룸 (구현보다 아이디어로 점수)

### 7-3. 기존 서비스와 겹침 처리
- 레시피 추천: 장볼지도 AI 레시피와 겹침 → 재료를 같은 시장 점포로 연결 + 재고 역추천으로 구분
- 넣지 않음: 온누리상품권 사용처 표시(정부가 네이버·카카오 지도로 제공 예정), 온라인 주문·배달(배민·네이버 운영 중, 우리 목표는 현장 방문)

### 7-4. 활성화 효과 지표 (발표 기대효과용)
- 인식 후 지도에서 점포를 누른 비율
- 레시피·재고 역추천 후 재료 점포로 이동한 비율
- 판단 카드 생성·공유 수
- 시장 시세표에 쌓인 가격 수, 상인 노하우 등록 수
- 다국어 사용 비율

### 7-5. 발표용 문장
> Market-On은 상인의 경험을 지식으로, 소비자의 사진을 시세로, 남는 재고를 레시피로 바꿔 전통시장이 가진 자산을 데이터로 활성화한다.

> 현장의 구매 판단(신뢰) → 점포 지도와 레시피 재료 안내(발견) → 판단 카드 공유(확산)로 소비자가 시장 안 여러 점포를 방문하게 만든다.

## 10. Wayket에서 얻은 참고 지식 (코드는 가져오지 않음)

김병수의 Wayket 논문 프로젝트(YOLO11 과일 인식 + KAMIS + OSRM 도로 거리 기반 시장 추천)에서 확인한 사실이에요. 아이디어와 판단 근거로만 쓰고, 코드·모델·데이터는 대회장에서 새로 만들어요.

- **품목 인식 정확도의 현실:** 13종 과일 2,288장으로 학습한 YOLO11s-seg도 mAP50 73.6%, 재현율 약 68%였어요. 과일이 겹치거나 쌓인 사진에서 많이 놓쳐요. 직접 학습 없이 범용 모델이나 API를 쓰면 더 낮을 수 있으니, **인식 결과를 사용자가 확인·수정하는 화면**을 두는 게 안전해요.
- **범용 모델의 오인식 사례:** 사전학습 yolo11n이 복숭아를 사과로 인식(신뢰도 0.47~0.50)한 적이 있어요. "범용 인식 + 온톨로지 매핑"이 필요한 근거로 쓸 수 있어요.
- **KAMIS 가격 단위 처리:** 품목마다 단위가 달라요(사과·배 10개, 샤인머스캣 2kg, 바나나 100g 등). 소비자에게는 1kg·1개·1송이처럼 실제로 사는 단위로 바꿔 보여 주는 게 좋았어요. 가격이 비면 지역 가격 → 전국 평균 → 최근 유효 가격 순으로 대체했어요.
- **지역별 가격 차이 예시 (2026-10 KAMIS 소매가, 조사지역 기본 품종):** 배 10개 강릉 17,900원 vs 제주 44,950원(2.5배), 사과 10개 세종 14,900원 vs 포항 33,800원(2.3배), 샤인머스캣 2kg 천안 7,580원 vs 부산 15,800원(2.1배)
- **가격만 쫓으면 손해라는 근거:** Wayket 실험에서 최저가 시장만 고르면 평균 39km를 가야 해서, 1.6만 원 장바구니의 총비용이 2배가 됐어요. "가까운 전통시장에서 현명하게 사기"라는 Market-On 방향의 근거로 쓸 수 있어요.
- **비슷한 서비스 조사 결과:** 6장 참고
