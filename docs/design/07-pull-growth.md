# 07. 찾아오게 만드는 구조 — 점포별 가격 · 입점 요청 · 시장 관리자

> 상태: **[제안]** 2026-11-24 (병수 방향 결정, 세부는 승인 대기)
> 방향 (병수): **우리가 시장에 부탁하지 않는다. 시장·점포·상인이 Market-On에 사용을 요청하게 만든다.** 이 "찾아오게 만드는 구조"를 프로젝트의 핵심으로 강조한다.

---

## 1. 소비자 흐름 [확정 2026-11-24]

```
시장: 현재 위치(GPS)로 가장 가까운 시장 자동 선택 (멀거나 위치 거부 시에만 목록)
입력 (둘 중 하나)
  · 사진 1장 — 상품과 가격표가 함께 보이게 → 품목 + 가격 + 단위를 한 번에 읽음
  · 직접 입력 — 품목 이름 + 가격 (입력 시 가격 필수)
→ 품목 확인 (대파가 맞나요? / 쪽파)  · 가격 확인 (3,000원 / 1단, 고칠 수 있음)
→ 결과: 확인 포인트 + 기준시세 대비 ±% + 이 시장 판매 점포·점포별 가격
→ 동시에 저장: 이 시장(+점포) 품목 가격 = 손님 가격 제보
```
- **가격표가 없으면 그냥 넘어가요**: 사진에 가격표가 안 보이면 묻거나 막지 않고 바로 결과로 가요. 결과는 확인 포인트 + 기준시세만 보여 주고(±% 없음), 가격 칸은 비어 있는 선택 입력. 이 경우 가격 제보는 저장하지 않아요
- 직접 입력(이름)일 때만 가격이 필수예요
- 컨셉 유지: "가장 싼 시장 찾기"가 아니라 **시장 안 상품 앞에서 "이걸 살까" 판단** (CONTEXT 6-2)

## 2. 점포별 가격 = 손님이 비교하면서 남기는 값 [확정: B 보류 해제]

상인·관리자는 가격을 입력하지 않아요. 손님이 **비교하려고 찍은 사진·입력한 가격**이 그대로 쌓여요.

| 단계 | 손님이 얻는 것 | 쌓이는 것 |
|---|---|---|
| 사진(가격표 포함) 또는 이름+가격 | 기준시세 대비 ±%, 확인 포인트 | 품목·가격·단위·시각·시장 (+점포) |

**점포 정하기 (손님에게 따로 묻지 않는 순서)**
1. 점포 QR(포스터)로 들어옴 → 그 점포
2. 지도·판매 점포 목록에서 점포를 누르고 들어옴 → 그 점포
3. 그 외 → 결과 아래 "어느 가게예요?" 근처 판매 점포 칩 (건너뛰면 시장 단위로만 저장)

**믿을 수 있게**
- 점포 가격 표시: "손님 3명 확인 · 오늘 14:20" (최근 값, 서로 비슷한 값의 중앙값, 혼자 튀는 값 제외)
- 상인이 확인 버튼을 누르면 "상인 확인" (상인 할 일은 이것뿐, 선택)
- 개인정보 없음: 기기 단위 익명 표시로 같은 사람 중복만 막음
- 오래된 값은 날짜와 함께 흐리게, 7일 지나면 숨김

**DB**: 기존 `price_reports` 사용 (method `price_tag_photo`·`manual`, `media_id`, `store_id` 선택) + `device_hash` 열 추가 / 집계는 조회 시 계산

**발표 문장**: "상인도 관리자도 가격을 입력하지 않습니다. 손님이 비교하려고 찍은 사진 한 장이 쌓여 시장의 가격표가 됩니다."

## 3. 시장·점포·상인이 요청하게 만드는 구조

### 3-1. 역할 (지금 2단계 → 3단계)
| 역할 | 누가 | 하는 일 |
|---|---|---|
| 운영자 `operator` | Market-On 팀 | **시장 입점 신청만 승인** |
| **시장 관리자 `market_admin`** [신규] | 상인회·시장 관리사무소 | 자기 시장 등록 정보, **자기 시장 상인 가입 승인**, 구역·점포 배치 확인 |
| 상인 `merchant` | 점포 주인 | 점포 정보·취급 품목·오늘 가격·마감세일 |
- 상인 승인을 시장 관리자에게 넘겨서 **우리 일은 시장 1곳 승인으로 끝나요**. 시장이 늘어나도 우리 운영 부담이 늘지 않아요

### 3-2. 요청이 들어오는 경로
| 경로 | 장치 |
|---|---|
| **소비자 → 시장** | 지원하지 않는 시장을 고르면 "이 시장도 쓰고 싶어요" 버튼. **요청 수가 쌓임** (개인정보 없이 숫자만) |
| **수요 데이터 → 시장** | 시장 입점 신청 페이지에 공개: "이번 주 이 시장 근처에서 품목을 찾아본 사람 N명, 이 시장을 요청한 사람 N명" → 시장이 들어올 이유 |
| **시장 → 우리** | `/join` 입점 신청 페이지: 시장 이름·관리 주체·담당 연락처(시장 공식 연락처만)·점포 수 → 운영자 승인 → 시장 관리자 계정 발급 |
| **상인 → 시장** | 시장이 입점되면 상인은 가입 → **시장 관리자가 승인**. 이미 가입한 옆 점포가 "본 사람 N명"을 받는 걸 보고 따라 가입 |
| **QR 포스터** | 점포 QR(이미 있음) + **시장 입구 QR 포스터**(시장 관리자 화면에서 인쇄) |

### 3-3. 들어올 이유 (시장·상인 입장)
- 손님이 **"어디서 살까"가 아니라 "이 시장 어느 점포"**로 바로 옴 (지도·판매 점포 강조)
- 가격·마감세일을 올린 점포가 먼저 보임 → 올릴수록 손님이 옴
- 시장 관리자에게 **시장 단위 숫자**: 찾아본 품목 순위, 점포 조회 수 합계 (개인정보 없음)
- 비용·설치 없음: 휴대폰 웹, QR 인쇄만

## 4. 발표에서 강조할 문장
> **"Market-On은 시장에 부탁하지 않습니다. 소비자의 요청과 숫자가 쌓이면, 시장과 상인이 먼저 찾아옵니다."**

- 근거 장면: 지원 안 되는 시장 → "요청" 숫자 증가 → 입점 신청 페이지에 수요 숫자 → 시장 관리자 승인 → 상인 가입 → 가격 올린 점포가 먼저 보임

## 5. 기존 설계와 바뀌는 곳
- 05 문서: 역할에 `market_admin` 추가, 상인 승인 주체 = 시장 관리자 (운영자는 예외적으로 가능)
- 04 문서: `markets.status`(`requested`·`active`) 추가, `market_requests`(시장별 요청 수, 하루 단위), `market_applications`(입점 신청), `store_prices`
- 상인 기능 범위는 그대로 (점포 정보·취급 품목·마감세일) + 손님 제보 가격 "확인" 버튼(선택)
