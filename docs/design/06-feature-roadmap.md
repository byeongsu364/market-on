## 2. 구현 순서

### 1단계 · 시연 핵심 흐름을 실제 데이터로 [완료 2026-11-24]
| 작업 | 내용 |
|---|---|
| 1-1 ✅ | 품목·시장 API (`/items`, `/markets/nearby`, `/markets/{id}/map`) |
| 1-2 ✅ | `GET /price` 계약, 단위 환산, 사과 후지 |
| 1-3 ✅ | 사진 인식 (`/recognize`, 온톨로지 목록 안에서) |
| 1-4 ✅ | 가격표 읽기 + 손님 가격 제보 |
| 1-5 ✅ | 프론트 실제 API 연결 + 새 소비자 흐름 |

### 1.5단계 · 찾아오게 만드는 구조 (07 문서) [확정 · 2026-11-25 완료]
| 작업 | 내용 |
|---|---|
| P-1 이름+가격 입력 · 시장 자동 ✅ | 찍기와 함께 품목 이름 + 가격(필수) 입력, GPS로 가까운 시장 자동 선택 |
| P-2 결과 → 판매 점포 목록 ✅ **(주 기능)** | 결과 화면에서 바로 "이 시장 판매 점포 N곳" + 점포별 가격, "어느 가게예요?" 칩 |
| P-3 점포별 가격 표시 ✅ **(확장 기능)** | 손님 제보 집계 ("손님 3명 확인 · 오늘 14:20"), 상인 확인 버튼(선택) |
| P-4 시장 관리자 역할 ✅ | `market_admin`, 자기 시장 상인 승인 (운영자는 시장 승인만) |
| P-5 입점 요청 흐름 ✅ (전국 시장 목록은 DATA_GO_KR_KEY 활용신청 후 적재) | 소비자 "이 시장도 쓰고 싶어요" 요청 수, `/join` 입점 신청, 수요 숫자 공개 |

### 2단계 · AI 답변과 챗봇 (D4~D6 · H) — 진행 중
| 작업 | 상태 | 내용 |
|---|---|---|
| 2-0a 근거 문서 초안 | ✅ | 5품목 × 4종류 = 20개, 농촌진흥청 출처, 팀 검수는 md 파일 직접 수정 |
| 2-0b 모델 라우팅 | ✅ | 기본 Gemma, 부족하면 GPT(`gpt-5.4-mini`), 대화는 GPT 먼저. GPT 장애 시 Gemma 결과 유지 |
| 2-1 `POST /ask` | ✅ | 의도 → 품목 → (가격·판매 점포는 LLM 없이) → 캐시 → 검색 → 답변 → **값 대조(D5)** → 출처 |
| 2-2 물어보기 화면 | ⬜ | 결과 화면 질문 칩 + 자유 질문 + 출처 표시 |
| 2-3 `POST /recommend` | ⬜ | 품목·수량·예산은 코드가 계산, 이유 문장만 LLM (H1·H2) |
| 2-4 대화형 질문 | ⬜ | 채팅 화면, 기존 기능을 도구로 (H3) |

### 3단계 · 레시피·손질법·재고 (F)
- 식품안전나라 레시피 DB → RAG `recipe` 문서, 재료 → 온톨로지 품목 → 같은 시장 판매 점포 (F1·F2)
- 손질법(`prep`)·생필품 사용법(`guide`) 문서와 결과 화면 탭
- 상인 "남는 재고" 버튼 (상인 페이지에 추가, F3) → 그 재료로 만드는 레시피 역추천 (F4)
- 날씨 맞춤 (기상청 단기예보, 실패 시 제철, F5)

### 4단계 · 카드·다국어·알림·PWA (G · I2 · I3 · J3)
- 판단 카드: 브라우저에서 그림 생성 (확인 포인트 체크 결과·기준시세·출처) → 저장·공유 (G1·G2)
- 다국어 번역 (Gemma로 초안 → 팀 검수), 외국인 주문 문장 카드 (G3·G4)
- 알림: 앱 안 알림(관심 품목 마감세일) 먼저, 브라우저 푸시는 HTTPS 배포 후 (I2)
- 편의시설 층 (I3), PWA 설치 (J3)

### 데이터 작업 (팀원과 함께, 단계와 병행)
- D1·D2: 시연 품목 30개 온톨로지·확인 포인트·저장 조건 (출처 있는 문서 기준)
- E1: 경동시장 상가정보 점포 → 카테고리 지정 → 미니맵 배치 (현장 확인)
