# Market-On 1차 중간 보고서

Nov 26, 2026 · @김진용

## 요약
전통시장은 싸고 신선하지만, 소비자는 상품 앞에서 그걸 확인할 근거가 없어 망설이고 상인의 강점은 홍보되지 못함. Market-On은 판단 근거와 선택 시의 장점을 건네 선택을 돕고, 그 선택을 시장 안 점포로 잇는 방식으로 해결함.

| 문제점 | 근거 | 우리의 해결 | 기능 |
| --- | --- | --- | --- |
| 가격이 적당한지 모른다 | 전통시장 채소류가 대형마트보다 52.7% 저렴하지만 현장에서 확인할 방법이 없음 | KAMIS 기준시세 대비 ±%를 실제 사는 단위(단·개·kg)로 환산해 보여 줌 | F4 |
| 품질을 믿지 못한다 | 전통시장 상품 품질 만족 29.1% | AI가 판정하지 않고, 품목별 확인 포인트를 출처와 함께 제시함. 신선도는 소비자가 3초 안에 체크 | F1 |
| 고르다 지치고, 산 뒤 후회한다 | 고르는 법·적정가를 모르는 2030 장보기 초보 | 근거 엔진이 가격·제철·양·보관을 비교해 추천안 1개와 대안 1개를 제시하고, "이걸 사면" 얻는 장점·활용을 함께 보여 줌. 선택은 소비자가 함 | F2·F3 |
| 점포가 보이지 않는다 | 시장 안 점포 디지털 지도 등록률 12% 미만 | 시장 안 점포를 카테고리 지도로 보여 주고, 추천 품목을 파는 점포를 강조함 | F5 |
| 상인은 홍보 수단이 없다 | 50대 상인, 앱이 어렵고 입력할 시간이 없음 | 오늘 추천을 30초 만에 올리면 소비자 화면과 지도에 바로 뜨게 함 | F7 (P1) |
| AI 답변을 믿기 어렵다 | 생성형 AI의 환각 | 온톨로지가 검색 범위를 좁힌 RAG로 답하고, 답변마다 출처를 붙임. 근거가 없으면 "확인된 자료가 없어요" | F1·F6 |

• 부제: 판단 근거는 Market-On이, 선택은 당신이
• 상인용: 망설이던 손님, 우리 가게로 On

## 1. 프로젝트 개요

한 줄 정의는 \*\*"시장 안에서, 이 상품을, 내가 판단한다."\*\*이다. 사용자 흐름은 고르고 → 비교하고 → 납득하고 → 구매한다 4단계다.

| 항목 | 내용 |
| --- | --- |
| 주제 | 지역사회 문제 해결 — 소상공인 홍보 |
| 팀 | 경복대학교 Market-On · 지도교수 신효영 |
| 팀원 | 김진용(대표, PM) · 김강현 · 김병수 · 신태빈 |
| 형태 | 모바일 웹(PWA) |

### 팀이 정한 원칙
1. **신선도는 소비자가 판단한다.** AI는 등급·"구매 추천"을 말하지 않고, 품목별 확인 포인트와 볼 위치만 안내한다.
2. **모든 지식과 숫자에는 출처가 붙는다.** 근거가 없으면 "확인된 자료가 없어요"라고 답한다.
3. **P0 핵심 흐름은 LLM 없이 동작한다.** Gemini가 막혀도 시연이 멈추지 않는다.

### 핵심 질문 3문항

| 질문 | 답 |
| --- | --- |
| 핵심 문제 | 전통시장은 싸고 신선한데, 소비자가 상품 앞에서 그걸 확인할 근거가 없어 망설임. 그래서 상인의 강점이 홍보되지 못함 |
| 핵심 사용자 | 고르는 법과 적정가를 모르는 2030 1\~2인 가구 장보기 초보. 부 사용자는 50대 상인, 외국인 방문객 |
| 핵심 기능 | ① 판단 근거 제공(가격·제철·양·보관) ② 선택 시 장점·활용 안내 ③ 시장 안 점포 연결과 상인 오늘 추천 |

## 2. 문제 정의와 근거

핵심 문제는 **정보 비대칭**이다. 전통시장의 가격·신선도 강점이 소비자에게 증거로 전달되지 않고, 그래서 상인의 강점이 홍보되지 않는다.

| 층위 | 근거 | 출처 |
| --- | --- | --- |
| 가격은 이미 유리하다 | 추석 차례상 조사에서 전통시장 채소류가 대형마트보다 52.7% 저렴 | [소진공 조사 보도](https://www.wikitree.co.kr/articles/1159542) |
| 품질은 믿지 않는다 | 전통시장 상품 품질 만족 29.1% | [세계일보 설문](https://www.segye.com/view/20231130519379) |
| 표시도 믿지 않는다 | 수산물 구매 시 추가 정보 필요 62.2%, 심층면접 "전통시장 표시는 신뢰하기 어렵다" | [한국소비자연맹](https://brunch.co.kr/@ngo201/1636) |
| 점포가 보이지 않는다 | 시장 안 점포 디지털 지도 등록률 12% 미만 | 서울시 분석(팀 컨텍스트 문서) |
| 가격만 좇으면 손해다 | 최저가 시장만 고르면 평균 39km 이동, 1.6만 원 장바구니의 총비용이 2배 | Wayket 실험(지식만 참고) |

**대회 주제 연결:** 소비자에게 판단 근거가 없다는 것은 상인의 강점이 증거로 전달되지 않는다는 뜻이고, 그게 곧 소상공인 홍보 문제다. Market-On은 근거를 현장에 보여 주고, 판단을 점포 방문으로 잇는다.

## 3. 사용자 정의

주 사용자는 시장에 익숙하지 않은 2030 소비자다. 구분 기준은 성별이 아니라 장보기 경험이고, 개인정보(이름·연락처·나이·성별)는 받지 않는다. 60대 단골은 이미 고르는 법을 알기 때문에 새로 끌어올 고객이 아니다.

| 페르소나 | 상황 | 망설이는 이유 | Market-On이 주는 것 | 단계 |
| --- | --- | --- | --- | --- |
| A. 장보기 초보 (28세 사회초년생, 1인 가구) | 퇴근길 동네 시장, 1\~2인분 장보기. 평소엔 마트·온라인 | 싱싱한지 모름, 적정가를 모름, 물어보기 민망 | 확인 포인트 3개, 기준시세 대비 ±%, 파는 점포 | P0 |
| B. 시장 상인 (50대, 청과 점포) | 손님이 지나치기만 함, 홍보 수단 없음 | 앱이 어렵고 입력할 시간이 없음 | 최초 1회 점포·취급 품목 등록, 오늘 추천 30초 | P1 |
| C. 외국인 방문객 | 시장 구경·먹거리 탐방 | 품목명을 모름, 한국어 안내문 | 다국어 라벨(ko·en·zh·ja·vi) | P1 |

### 핵심 시나리오 (페르소나 A, 대파 한 단)

1. 시장 입구에서 앱을 열면 GPS로 시연 시장이 자동 선택된다.
2. 채소 가게 매대를 찍고, 대파 박스를 탭한다. "green onion" 라벨이 대파·쪽파·실파 후보로 바뀌고, 대파를 확정한다.
3. 확인 포인트 3개(잎 끝 · 흰 줄기 · 뿌리 쪽)가 출처(농사로)와 함께 나오고, 사용자가 직접 체크한다.
4. 가격표의 3,500원을 입력하면 "기준시세(1단 환산) 대비 ▼12%"가 조사지역·조사일과 함께 나온다.
5. "파는 점포 보기"를 누르면 미니맵에서 채소 구역 점포 3곳이 강조된다.
6. (P1) 상인 오늘 추천과 "함께 사기: 두부·양파"로 다른 점포까지 동선이 이어진다.

**보조 시나리오 (페르소나 B):** 상인이 내 점포를 탭하고 오늘 추천(단감 5개 1만 원)을 올리면 소비자 홈과 지도에 바로 뜬다.

## 4. 경쟁·차별점

기존 서비스가 "시장에 어떻게 가나", "집에서 어떻게 사나", "어디가 싸나"를 풀었다면, Market-On은 시장 안에서 상품 앞에 선 순간의 판단을 돕는다.

| 서비스 | 하는 일 | Market-On과 관계 |
| --- | --- | --- |
| 알뜰하게 장볼지도 (농식품부·aT) | 매장 가격 지도, AI 레시피, 최적 구매처 | 가격 비교·레시피 중복 → "내 앞 이 상품이 싸나"로 구분, 레시피는 만들지 않음 |
| 서울시 전통시장 입체주소 | 점포 앞까지 길 안내 (서울 일부 시장) | 점포 지도 중복 → "인식한 품목을 파는 점포"로 연결 |
| 배민스토어·네이버 동네시장 | 전통시장 배달 | 온라인 주문, 현장 판단과 다름 |
| 신선도 판정 앱 (프레시 체커 등) | AI가 신선도 판정 | AI 판정 vs 소비자 판단 |
| 쿠팡·컨리 AI 선별 | 판매자 내부 품질 검수 | 소비자용 아님 |

### 차별점 4가지

| 축 | 기존 서비스 | Market-On |
| --- | --- | --- |
| 쓰는 장소 | 집에서 "어디서 살까" | 시장 현장에서 "이걸 살까" |
| 판단 주체 | AI가 등급 판정 | 소비자가 확인 포인트로 판단 |
| 근거 출처 | 생성형 AI의 말 | 온톨로지 + RAG, 답변마다 출처 |
| 혜택 대상 | 소비자 | 소비자 + 상인(점포 연결·오늘 추천) |

## 5. 서비스 범위와 기능 정의

기능은 13개이고, 번호 순서가 곧 개발 순서다. P0(F1\~F5)는 24:00까지, P1은 05:00 기능 동결 전까지, P2는 여유가 있을 때만 하거나 로드맵으로 발표한다.

| ID | 기능 | 핵심 기능 묶음 | 신청서 기능 번호 | 단계 |
| --- | --- | --- | --- | --- |
| F1 | 지식 기반 (온톨로지 + RAG) | 공통 기반 | 3 | P0 |
| F2 | 사진 품목 인식 + 사용자 확정 | ① 찍고 판단 | 1 | P0 |
| F3 | 품목별 확인 포인트 안내 (등급 없음) | ① 찍고 판단 | 1 | P0 |
| F4 | KAMIS 기준시세 대비 가격 위치 | ② 가격 위치 | 2 | P0 |
| F5 | 시장 안 점포 카테고리 지도 | ③ 찾고 알린다 | 6 | P0 |
| F6 | 근거 기반 답변·환각 억제 | 공통 기반 | 3 | P1 |
| F7 | 상인 오늘 추천 (점포·취급 품목 등록 포함) | ③ 찾고 알린다 | 5 | P1 (첫 번째) |
| F8 | 확인 위치 안내 (Gemini, 크롭 이미지) | ① 찍고 판단 | 1 | P1 |
| F9 | AI 구매 추천 Agent (가정용·선물용·제수용, 예산) | 부가 | 4 | P1 |
| F10 | 다국어 (ko·en·zh·ja·vi) | 부가 | 5 | P1 |
| F11 | 온톨로지 기반 응답 캐시 | 공통 기반 | — | P1 |
| F12 | 함께 사기·장보기 동선 | ③ 찾고 알린다 | 6 | P2 |
| F13 | Gemini ⇄ Gemma 모델 전환, 구매 판단 카드 | 부가 | AI 도구 · 5 | P2 |

**11-22 기획서에서 바뀜 점:** 상인 오늘 추천을 F8에서 F7로 당겨 P1 첫 번째로 두었다. 확인 위치 안내(F8)를 새로 넣었고, P0가 LLM 없이 돌도록 P1에 두었다.

### 제외 범위 (만들지 않음)

- **AI 신선도 등급 판정:** 카메라는 표면만 보고, 평가 데이터도 없으며, 책임 문제가 있다 (7장 Vision 설계).
- **판매 로그 트렌드 대시보드:** 판매 데이터 출처가 없다.
- **레시피 추천:** 장볼지도와 정면 중복이다. F12의 연결 고리로만 쓴다.
- **온누리상품권 사용처:** 정부가 네이버·카카오 지도로 제공한다.
- **회원가입·결제·주문:** 목적은 현장 판단이다.

## 6. MVP 정의

MVP는 "찍고 → 판단하고 → 가격 보고 → 찾는" 한 흐름이고, 아래 완료 기준을 모두 넘으면 P0 완료로 본다. 완료 기준은 그대로 테스트 항목으로 쓴다.

### 사용자 스토리와 완료 기준 (P0)

| ID | 사용자 스토리 | 완료 기준 (Definition of Done) | 화면 · API |
| --- | --- | --- | --- |
| F1 | 개발자로서, 품목 지식을 출처와 함께 조회하고 싶다 | 시연 품목 30개 노드, 품목마다 확인 포인트 3개 + `source_id`, P0 문서(A·B·C) 벡터DB 적재 | — · 내부 |
| F2 | 소비자로서, 매대 사진에서 고른 상품의 품목명을 알고 싶다 | 박스 탭 선택, 후보 3개 안에 정답(시연 품목 10개 중 9개), 후보에 없으면 검색, 사진 → 후보 5초 이내 | S2 · `POST /recognize` |

## 7. 기술 설계

역할 분담은 \*\*"Vision은 눈, 온톨로지는 기준, RAG는 근거, Gemini는 설명, KAMIS는 가격, 소비자는 판단"\*\*이다. 사용자가 확정한 `item_id` 하나로 확인 포인트·시세·점포를 그래프에서 바로 조회하므로, P0는 Gemini가 막혀도 동작한다.

&#91;embedded content: 요청 처리 흐름 · P0 7단계, P1 LLM 경로 5단계\]

점선 아래(P1)만 LLM을 쓴다. 모든 질문은 온톨로지 정규화를 거친 뒤에야 Gemini에 닿는다.

### Vision 사용 방식

Vision은 "무엇인가·어디를 볼까"만 맡고, 신선도 판정은 맡기지 않는다.

| 단계 | 호출 | 하는 일 |
| --- | --- | --- |
| 1 | `OBJECT_LOCALIZATION` | 매대 사진에서 상품 박스를 찾고, 사용자가 하나를 탭해 자른다 |
| 2 | `LABEL_DETECTION` | 일반 라벨(예: Allium)을 `vision_labels`로 매핑해 후보 3개를 만든다 |
| 3 | (없음) | 사진이 너무 어둡거나 흐리면 다시 찍기를 안내한다 |
| 4 (P1) | Gemini, 크롭 이미지 | 확인 포인트별로 볼 위치만 짚는다. 합격·불합격은 말하지 않는다 |

신선도를 판정하지 않는 근거는 다섯 가지다. Vision에 신선도 기능이 없고, 폰 카메라는 당도·경도 같은 내부 품질을 보지 못한다. 연구 데이터는 대부분 단색 배경·일정 조명이라 시장에서 일반화되지 않고, 무박 일정에는 학습 데이터를 만들 수 없으며, 틀렸을 때 책임 문제가 생긴다 ([AI 신선도 탐지 리뷰](https://nepjol.info/index.php/jjmc/article/download/97996/74350/283114), [국립농업과학원 연구](https://www.kais99.org/jkais/journal/Vol24No12/vol24no12p062.pdf)).

### 온톨로지·RAG

- **역할:** 온톨로지는 짧은 사실과 관계("무엇을 찾을지"), RAG는 이유와 맥락("무엇이라고 답할지")을 맡는다.
- **P0 노드:** Item, Category(isA), Criterion(hasCriterion), PriceObservation(hasPrice), SaleUnit(soldBy), Market → Zone → Store(sells), Source(supportedBy)
- **RAG 문서:** P0는 A 품목 정보(농사로), B 품질 표준규격, C 시장·점포 이야기. 청크 300\~500토큰, 메타데이터 `item_id`·`node_type`은 온톨로지 노드 이름과 같다.
- **캐시 키:** `item_id + intent + 날짜`. "대파 값"과 "파 가격"이 같은 키에 적중한다.
- 상세는 프로젝트 문서 온톨로지\_아키텍처\_v2, RAG\_지식베이스\_v1을 따른다.
