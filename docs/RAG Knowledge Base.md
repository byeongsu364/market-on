# Market-On · RAG Knowledge Base

> **요약** — 온톨로지에는 **짧은 사실 값**(대파 제철 = 11월)을, RAG에는 **이유와 맥락이 담긴 긴 글**(왜 겨울 대파가 단지, 국내산과 수입산을 어떻게 구별하는지)을 넣어요.
> 문서 유형은 10종(A~J)이에요. 시연 품목 30개 기준으로 **문서 약 150개, 청크 1,000~1,500개**에 시장·점포 이야기 청크 100~200개를 더해요.
> 검색은 **온톨로지로 범위를 좁힌 뒤 벡터 검색**하는 하이브리드 방식이고, 모든 답변에 출처(`Source`)를 붙여요.
> 대회 전에는 출처와 라이선스 조사까지만 하고, 수집·청크 분할·임베딩은 대회 현장에서 새로 해요 (서약서 기준).
>
> 연결 문서: [`Market-On_Ontology_Architecture.md`](./Market-On_Ontology_Architecture.md) — 청크 메타데이터의 `item_id` · `node_type`은 온톨로지 노드 이름과 똑같이 써요.

## 1. 온톨로지와 RAG의 역할 구분

| 구분 | 온톨로지 (지식그래프) | RAG (문서 검색) |
|---|---|---|
| 담는 것 | 짧은 사실 값, 관계 | 설명, 이유, 맥락, 이야기 |
| 예시 | `대파 –inSeason→ 11월`, `점포 –sells→ 대파` | "겨울 대파는 추위를 견디려 당을 쌓아 단맛이 강해요" |
| 형식 | JSON-LD / rdflib 트리플 | 300~500토큰 청크 + 임베딩 |
| 역할 | 질문 정규화, 검색 범위 결정, 캐시 키 | 답변 본문과 근거 제공 |
| 틀렸을 때 | 구조 오류 → 검색 실패 | 내용 오류 → 출처로 추적 가능 |

**원칙:** 온톨로지가 "무엇을 찾을지"를 정하고, RAG가 "무엇이라고 답할지"를 채워요.

## 2. 문서 유형 10종

| # | 문서 유형 | 담는 내용 | 출처 후보 | 연결 노드 (`node_type`) | 단계 |
|---|---|---|---|---|---|
| A | 품목 정보 | 특징 · 고르는 법 · 보관법 · 손질법 | 농촌진흥청 농사로 | `Criterion` · `Storage` · `Prep` | P0 |
| B | 품질 표준규격 | 크기 · 색택 · 결점 기준, 등급 구분 | 국립농산물품질관리원 농산물 표준규격 | `Criterion` · `Variety` | P0 |
| C | **시장·점포 이야기** | 시장 역사 · 점포 소개 · 상인 한 줄 소개 · 대표 품목 | 시연 시장 누리집 · 상인 직접 입력 · 현장 인터뷰 | `Market` · `Store` · `TodayPick` | P0 |
| D | 제철 정보 | 이달의 수산물 · 이달의 음식 · 제철인 이유 | 해양수산부 이달의 수산물 · 농촌진흥청 이달의 음식 | `Season` | P1 |
| E | 원산지 구별 | 국내산·수입산 구별법 · 이력제 조회 방법 | 수산물·쇠고기 이력제 안내 | `OriginTip` (신규) | P1 |
| F | 축산 등급 해설 | 1++·1+ 등급 표시의 뜻 · 부위별 용도 | 축산물품질평가원 | `Variety` · `Context` | P1 |
| G | 안전 주의 | 잔류농약 분석 결과 · 손질 주의(복어·패류 등) | 국립농산물품질관리원 잔류농약 분석결과 API | `SafetyNote` (신규) | P1 |
| H | 구매 맥락 지식 | 제수용 품목 · 명절 선물 관례 · 김장 재료와 양 | **[확인 필요]** | `Context` | P1 |
| I | 지역 특산물 | 산지별 특산품 · 산지 특징 | 농촌진흥청 지역특산물 | `Region` (`specialtyOf`) | 선택 |
| J | 외국인 안내 | 시장 이용법 · 간단한 주문 문장 | 팀 작성 + 다국어 번역 | `Item` (`labels_i18n`) | 선택 |

### 온톨로지에 추가할 노드
- `OriginTip` (원산지 구별): `item_id` · `domestic_sign` · `imported_sign` · `trace_guide` · `source_id`
- `SafetyNote` (안전 주의): `item_id` · `type`(잔류농약/손질/알레르기) · `note` · `source_id`

### 라이선스 처리 규칙
1. **1·2유형:** 요약하거나 바꿔 써서 답변해도 돼요. 출처는 표시해요.
2. **3·4유형:** 요약하거나 바꿔 쓰지 않아요. **원문 인용 + 출처 표시**만 해요. 청크에 `quote_only: true`를 붙여요.
3. **상인 입력:** 입력 화면에 "서비스 안 홍보에 쓰여요"라는 동의 문구를 넣어요.
4. **라이선스를 확인하지 못한 문서:** 수집하지 않아요.

## 4. 청크 규칙과 메타데이터 스키마

### 4-1. 청크 규칙
- 크기 300~500토큰, 앞뒤 50토큰 겹침
- 한 청크에는 **한 품목의 한 주제**만 담아요. 예: 대파 고르는 법과 대파 보관법은 다른 청크예요.
- 표는 행 단위로 풀어서 문장으로 바꿔요. 예: "대파 특 등급: 흰 줄기 길이 ○cm 이상"
- 시장·점포 이야기(C)는 점포 1곳 = 청크 1~3개로 만들어요.

### 4-2. 메타데이터 스키마

| 필드 | 예시 | 용도 |
|---|---|---|
| `chunk_id` | `chk:nongsaro-green_onion-03` | 고유 ID (`Source.chunk_id`와 연결) |
| `item_id` | `item:green_onion` | **온톨로지 연결 키**, 검색 필터 |
| `node_type` | `Criterion` | **온톨로지 연결 키**, 의도별 필터 |
| `intent` | `select` / `store` / `price` / `origin` / `season` / `safety` / `story` | 질문 의도 필터 |
| `market_id` · `store_id` | `market:mangwon` · `store:mangwon-B03` | 시장·점포 이야기 필터 |
| `source_id` | `src:nongsaro` | 출처 표시 |
| `published` | `2026-03-05` | 최신성 판단 |
| `lang` | `ko` | 다국어 |
| `license` | `KOGL-1` / `KOGL-4` / `merchant-consent` | 라이선스 처리 |
| `quote_only` | `true` / `false` | 3·4유형이면 원문 인용만 |

```json
{
  "chunk_id": "chk:nongsaro-green_onion-03",
  "text": "대파는 잎 끝이 마르지 않고 흰 줄기가 단단하며 윤기가 있는 것이 좋다 ...",
  "item_id": "item:green_onion",
  "node_type": "Criterion",
  "intent": "select",
  "market_id": null,
  "store_id": null,
  "source_id": "src:nongsaro",
  "published": "2026-01-15",
  "lang": "ko",
  "license": "KOGL-1",
  "quote_only": false
}
```

## 5. 하이브리드 검색 흐름 (대파 예시)

```text
질문 "이 대파 국산 맞아요?"
  │
  ▼ ① 온톨로지 정규화
  item_id = item:green_onion   (동의어: 파·대파값·green onion)
  intent  = origin
  │
  ▼ ② 메타데이터 필터 (검색 범위 축소)
  WHERE item_id = item:green_onion AND node_type IN (OriginTip, Criterion)
  │
  ▼ ③ 벡터 검색 (상위 3~5개 청크)
  chk:trace-green_onion-01, chk:nongsaro-green_onion-03 ...
  │
  ▼ ④ 답변 생성 + 근거 검증
  - 청크에 없는 내용은 답하지 않음 → "확인된 자료가 없어요"
  - quote_only 청크는 원문 그대로 인용
  │
  ▼ ⑤ 출처 표시
  "근거: 농사로 대파 정보 (2026-01-15)"
  │
  ▼ ⑥ 캐시 저장
  key = item:green_onion + intent:origin + 2026-11-28
```

**발표 포인트:** "온톨로지가 RAG의 검색 범위를 정해요. 문서가 1,000개를 넘어도 다른 품목 문서가 섞이지 않아요."
