기술마다 **어떤 기술인가**(정의)와 **우리는 어디에 쓰는지**를 한 줄씩 정리했어요. "상태" 칸은 11/26 저장소(main `58053e3`) 기준으로, 발표에서 "쓰고 있다"고 말해도 되는지 구분하는 데 써요.

## 서버 (백엔드) · 데이터베이스

서버는 Python으로, 데이터는 PostgreSQL 하나에 모아요. 온톨로지·문서 검색·시세·점포가 모두 같은 DB에 있는 게 우리 구조의 핵심이에요.

| 기술 | 어떤 기술인가 | 우리는 어디에 쓰나 |
| --- | --- | --- |
| Python 3.11 | AI·데이터 라이브러리가 많은 프로그래밍 언어 | 백엔드·데이터 적재 스크립트 전부 |
| FastAPI | Python으로 API 서버를 빠르게 만드는 프레임워크. API 설명서를 자동으로 만듦 | 사진 인식(`/recognize`)·시세(`/price`)·질문 답변(`/ask`)·시장·로그인·관리자 등 모든 API |
| Pydantic | 들어오는 데이터의 모양을 검사하는 라이브러리 | 요청·응답 형식 검사, `.env` 설정 읽기 (CORS `*` 금지 같은 규칙) |
| Uvicorn | FastAPI 앱을 실제로 띄우는 웹서버 프로그램 | 백엔드 실행 (127.0.0.1:8000) |
| 계층 구조 (router → service → repo) | 주소 처리 · 규칙 · DB 조회를 층으로 나눠 섞이지 않게 하는 설계 | SQL은 `db/` 폴더에만 둠 (팀 규칙) |
| PostgreSQL 16 | 가장 많이 쓰는 오픈소스 관계형 데이터베이스 | 온톨로지·문서·시세·시장·점포·계정·가격 제보 전부 |
| pgvector | PostgreSQL에서 벡터(숫자 배열) 유사도 검색을 하게 하는 확장 | RAG 문서 조각 검색 (1024차원) |
| psycopg 3 | Python에서 PostgreSQL에 접속하는 라이브러리 | 모든 쿼리. 값을 SQL과 따로 보내는 방식이라 SQL 인젝션 방어 |
| 마이그레이션 | DB 테이블 변경을 번호 붙은 SQL 파일로 순서대로 적용하는 방식 | `migrations/0001~0013`, `python -m scripts.migrate` |
| httpx | 다른 서버에 HTTP 요청을 보내는 라이브러리 | aT 시세·공공데이터·AI 모델 호출 (로그에 키가 안 남게 가림) |

## AI 모델

기본은 우리가 직접 띄운 모델(비용 0)이고, 부족할 때만 외부 모델로 다시 묻는 구조예요. 어느 모델이 답했는지는 항상 기록해요.

| 기술 | 어떤 기술인가 | 우리는 어디에 쓰나 | 상태 |
| --- | --- | --- | --- |
| LLM (대형 언어 모델) | 글을 이해하고 문장을 만드는 AI. 사진도 보는 모델은 멀티모달이라고 해요 | 사진 인식, 가격표 읽기, 질문 답변 | 사용 중 |
| Gemma (`gemma4:e4b`) | 구글이 공개한 오픈 모델. 내 컴퓨터에서 돌릴 수 있음 | 사진을 보고 온톨로지 품목 목록 안에서 고르기 + 같은 사진의 가격표 읽기 ("7천원" → 7,000) | 사용 중 (기본 모델) |
| Ollama | 오픈 모델을 내 컴퓨터에서 쉽게 실행하는 프로그램 | Gemma와 bge-m3를 띄움. 학교 서버에서 돌고 Tailscale로만 접속 | 사용 중 |
| 양자화 | 모델의 숫자 정밀도를 낮춰(예: 8비트) 메모리·속도를 줄이는 기술 | 작은 컴퓨터에서도 Gemma를 돌리기 위한 방식 | 배포 시 확인 |
| GPT (OpenAI) | OpenAI의 유료 언어 모델 | Gemma가 못 알아보거나 자신 없을 때(신뢰도 0.6 미만)만 다시 물음 | 코드 있음, 키·모델 미정 (설정 전에는 Gemma만 씀) |
| 모델 라우팅 | 작업마다 어느 모델을 어떤 순서로 쓸지 정하는 설정 | "사진 인식은 Gemma → GPT" 순서, 설정 하나로 변경 | 사용 중 |
| bge-m3 | 문장을 숫자 배열(임베딩)로 바꾸는 다국어 모델 | RAG 문서 조각과 질문을 1024개 숫자로 바꿔 비교 | 사용 중 |
| Gemini (Google) | 구글의 유료 AI 모델 | 초기 설계의 기본 모델. 코드는 남아 있지만 지금은 안 씀 | 미사용 |
| Google Cloud Vision | 구글의 사진 인식 서비스 | 초기 설계에 있었지만 11/25에 Gemma로 대체 | 미사용 |
| 호출 기록 (llm_calls) | AI를 부른 기록을 남기는 테이블 | 어느 모델이 몇 초 만에 답했는지, GPT로 넘어갔는지만 저장. 질문·사진·답변 내용은 저장하지 않음 | 사용 중 |
| 함수 호출 (Tool calling) | AI가 직접 답하는 대신 정해진 기능(시세 조회 등)을 골라 부르게 하는 방식 | 채팅 화면에서 GPT가 기존 기능(시세·점포·근거 답변)을 불러 답함 (2-4 대화형 질문) | 계획 |

## 지식 기술

온톨로지는 "무엇을 찾을지", RAG는 "무엇이라고 답할지"를 맡아요. AI가 지어낸 말 대신 근거 있는 답을 주는 것이 목표예요.

| 기술 | 어떤 기술인가 | 우리는 어디에 쓰나 | 상태 |
| --- | --- | --- | --- |
| 온톨로지 | 개념(품목)과 그 관계를 정해 둔 지식 구조 | 품목 중심으로 분류·제철·확인 포인트·판매 단위·출처를 연결 | 사용 중 |
| 지식그래프 | 온톨로지를 점(대상)과 선(관계)으로 이은 데이터 | `점포 → 판매 → 대파 → 제철 → 11월`처럼 따라가기 | 사용 중 |
| RDF · 트리플 | W3C 표준. 지식을 "주어 – 관계 – 대상" 세 칸으로 적음 | `entity_relations` 테이블이 이 모양 + 출처(`source_id`). 저장은 RDF 전용 DB 대신 PostgreSQL | 사용 중 (개념) |
| 정규화 (동의어·다국어) | 다른 표현을 하나의 표준 ID로 바꾸는 일 | "파", "대파값", "green onion" → `item:green_onion` (`entity_labels`) | 사용 중 |
| RAG | AI가 답하기 전에 관련 문서를 찾아 그 내용으로만 답하게 하는 방식 | 농사로 등 공공기관 문서를 근거로 답변 + 출처 표시 | 답변 API(POST /ask) 완성(11/26), 화면은 개발 중 |
| 임베딩 | 문장의 뜻을 숫자 배열로 바꾼 것. 뜻이 비슷하면 숫자도 가까움 | bge-m3로 문서 조각·질문을 변환 | 사용 중 |
| 벡터 검색 | 임베딩끼리 가까운 정도로 비슷한 문서를 찾는 검색 | 온톨로지로 범위를 먼저 좁힌 뒤 검색 (하이브리드 검색) | 사용 중 |
| 청크 (조각) | 긴 문서를 검색하기 좋게 자른 단위 | 약 500자, 50자 겹침. 조각마다 품목 ID·출처·라이선스 기록 | 사용 중 |
| 환각 억제 | AI가 근거 없는 말을 못 하게 막는 장치 | 근거 문서 안에서만 답하고 출처를 붙임. 답변의 숫자·품목을 원문과 대조하고 "신선해요·추천" 같은 판정 단어는 막음(fact check). 자료가 없으면 "이 품목의 ○○ 자료가 아직 없어요" | 사용 중 (11/26) |
| 응답 캐시 | 한 번 만든 답을 저장해 두고 같은 질문에 다시 쓰는 것 | 키 = 품목 ID + 의도 + 언어 + 날짜 + 문서 버전 + 질문. 질문 칩(고르는 법 등)은 같은 답을 공유하고, 자유 질문은 문장이 같을 때만 재사용. 문서가 바뀌면 자동으로 새 답 | 사용 중 (11/26) |
| 단위 환산 | 시세 단위를 사는 단위로 바꾸는 계산 | kg 시세 → "대파 1단(0.8kg)", 사과 "1개" (`soldBy` 관계의 환산값) | 사용 중 |
| 의도 분류 (intent) | 질문이 무엇을 묻는지 정해진 종류 중 하나로 고르는 일 | 고르는 법·보관·손질·제철·가격·판매 점포 6가지. 키워드로 먼저 고르고 안 되면 AI가 분류. 가격·판매 점포 질문은 AI 없이 바로 시세·점포로 답함 | 사용 중 (11/26) |

| SHA-256 + 솔트 | 값을 고정 길이 해시로 바꾸고, 비밀값(솔트)을 섞어 추측을 막는 방식 | 로그인 토큰은 해시만 DB에 저장, 손님 기기 ID는 `DEVICE_HASH_SALT`를 섞어 저장 | 사용 중 |
| 세션 쿠키 | 로그인 상태를 브라우저 쿠키로 유지. HttpOnly(스크립트 접근 차단)·Secure(https 전용)·SameSite(다른 사이트 요청 제한) | `mo_session`, 30일 유지. 거절·비활성하면 즉시 로그아웃 | 사용 중 |
| CSRF 방어 | 다른 사이트가 로그인된 사용자인 척 요청을 보내는 공격을 막음 | 상태를 바꾸는 요청에 `X-Requested-With: market-on` 헤더 필수 | 사용 중 |
| 계정 잠금 | 비밀번호를 여러 번 틀리면 잠시 막음 | 5번 틀리면 10분. 없는 아이디도 똑같이 잠겨서 가입 여부가 안 드러남 | 사용 중 |
| CORS | 어느 사이트가 우리 API를 부를 수 있는지 정하는 브라우저 규칙 | 우리 주소만 허용, `*`(모두 허용)는 서버가 안 켜지게 막음 | 사용 중 |
| Prepared Statement | SQL 문장과 값을 따로 보내 SQL 인젝션을 막는 방식 | 모든 DB 쿼리 (psycopg 3 파라미터 바인딩) | 사용 중 |
| `.env` / `.gitignore` | 비밀값을 코드와 분리해 파일에 두고 Git에 올리지 않는 방식 | API 키는 `.env`에만, GitHub에는 이름 양식(`.env.example`)만 | 사용 중 |
| HTTPS | 주고받는 데이터를 암호화하는 웹 통신 | 카메라·위치 기능과 Secure 쿠키에 필수 | 배포 때 |
| nginx | 웹서버. 요청을 받아 화면 파일을 주고 API는 백엔드로 넘김 | `/api` 떼고 전달, 숨김 파일·API 문서 차단, IP당 요청 횟수 제한, 보안 헤더 | 설정 파일 준비됨 |
| 방화벽(ufw) · fail2ban | 포트를 닫고, 로그인을 반복 시도하는 IP를 자동 차단 | 서버는 웹·SSH만 열고 SSH는 키 로그인만 (`harden.sh`) | 배포 때 |
| Tailscale | 허락된 기기끼리만 연결되는 사설 네트워크(VPN) | 서버가 학교 서버의 Ollama(AI)에 접속할 때만 사용. 학교망이 외부 접속을 막아도 동작 | 사용 중 |
| Cloudflare Tunnel | 서버 포트를 열지 않고 밖에서 접속하게 해 주는 터널 | HTTPS 방식 후보 (직접 인증서 받기와 비교 중) | 배포 방식 미정 |
